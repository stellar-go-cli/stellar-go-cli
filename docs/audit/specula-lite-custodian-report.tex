\begin{abstract}
\noindent
We applied the Specula Lite methodology — a lightweight, single-agent variant of
the Specula formal-verification pipeline — to the custodian signing daemon of
stellar-go-cli (\file{internal/custodian/}), the component that owns key custody,
enforces the operator policy (E1--E5), and brokers all passkey-protected and
mandate-delegated signatures. A hand-audited TLA+ model of the enforcement state
machine (~660 lines, file:line-annotated to the Go source) was exhaustively model
checked with TLC. All seven targeted hunt invariants produced counterexamples,
every one of which mapped to a concrete implementation defect — eleven confirmed
findings (F1--F11) including two rated \sev{high} severity: an unguarded agent
reactivation path and unsynchronized maps that produce an unrecoverable
\code{fatal error: concurrent map writes} remote crash. Each finding was
reproduced by an executable Go test. All findings were subsequently remediated;
the model was updated to match the fixed implementation and the hunts re-run:
four invariants now pass exhaustively at their bounds, one remains violated by
design (a documented capacity bound), and two show only a microsecond-scale
residual revocation window. The full test suite, race detector, \code{go vet},
and \code{golangci-lint} pass on the remediated tree.
\end{abstract}

\section{Introduction}
%==================================================================

The custodian daemon (\file{internal/custodian/}, $\approx$5{,}000 LOC) is the
security-critical core of the agent-facing signing architecture: it holds
passkey unlock grants in memory, enforces the operator policy
(\file{state/policy.json}) through the E1--E5 pipeline, brokers WebAuthn
ceremonies, manages mandate escrow for delegated agents, and appends every
decision to a hash-chained enforcement log. Because requests arrive over a Unix
socket on per-connection goroutines, correctness depends on subtle ordering and
synchronization invariants that unit tests struggle to cover — precisely the
class of defects model checking is designed to find.

This report documents a complete verification cycle:

\begin{enumerate}[nosep]
  \item \textbf{Model synthesis} — a TLA+ specification of the enforcement
        state machine, faithful to real lock boundaries.
  \item \textbf{Targeted hunts} — seven invariants checked under
        counter-bounded environment actions; all seven produced counterexamples.
  \item \textbf{Code mapping \& reproduction} — each counterexample mapped to
        concrete source lines and reproduced by a deterministic Go test.
  \item \textbf{Remediation} — all findings fixed in the implementation.
  \item \textbf{Re-verification} — model updated to match the fixes; hunts
        re-run; regression suite asserts the new behavior.
\end{enumerate}

\subsection*{Headline results}

\begin{itemize}[nosep]
  \item 7/7 hunt invariants violated pre-fix $\Rightarrow$ 11 confirmed
        findings (F1--F11): 2 \sev{high}, 4 medium, 5 low severity.
  \item Post-fix re-verification: 4 invariants \textbf{PASS} exhaustively;
        1 \textbf{expected violation} (accepted capacity bound, F11);
        2 \textbf{residual violations} confined to a microsecond commit-tail
        window (F9 remainder).
  \item Convergence run on the updated model: \textbf{20{,}032{,}814} states
        generated, \textbf{6{,}005{,}402} distinct, depth 22, full queue
        exhausted, no invariant violations.
  \item 15 \code{TestRepro\_*} regression tests assert the fixed behavior and
        go red if a defect returns.
\end{itemize}

\section{Scope and Methodology}
%==================================================================

\subsection{Toolchain}

Specula Lite is the officially supported lightweight path of the Specula
project: it preserves the agentic spec-synthesis $\rightarrow$ model-checking
$\rightarrow$ code-level reproduction loop while requiring no Specula
installation, MCP server, Maven, or agent adapter — only a JRE and
\code{tla2tools.jar}, bootstrapped into the per-user cache
(\file{.cache/specula-lite/}).
Checking was performed with TLC (TlaTools 1.8.0) under a bundled JRE 21:
\begin{lstlisting}
java -Xmx3g -XX:+UseParallelGC -cp tla2tools-1.8.0.jar \
  tlc2.TLC -deadlock -workers 4 -cleanup MC
\end{lstlisting}
All artifacts live in the (gitignored) \file{.specula-lite/} directory:
\begin{itemize}[nosep]
  \item \file{spec/base.tla} — the model; \file{spec/MC.tla} — checking wrapper
  \item \file{spec/MC.cfg} + seven \file{spec/MC\_hunt\_*.cfg} — run configs
  \item \file{modeling-brief.md}, \file{analysis-report.md}, \file{report.md} —
        methodology, audit trail, results
\end{itemize}
The durable review summary is
\file{docs/audit/specula-lite-custodian-findings.md}.

\subsection{System category and abstractions}

The daemon is a \emph{Category A} (message-passing) system: client
$\leftrightarrow$ Unix socket $\leftrightarrow$ per-connection handler
goroutines over in-memory stores, TTL-limited authority, and crash/restart with
log-based rebuild. The specification splits the E1--E5 pipeline at every real
mutex/store boundary — the same points where Go interleavings occur — rather
than collapsing the pipeline into one step. Key abstractions:

\begin{itemize}[nosep]
  \item WebAuthn ceremonies = atomic verify-or-fail oracles (the passkey itself
        is trusted hardware, not the system under analysis).
  \item XDR decode, Horizon I/O, socket-token check = environment.
  \item Request payloads are well-formed; refusals of interest are
        authority/escalation/replay/cap refusals, not parse errors.
  \item The $>$10k-entry seen-set aging gate is modeled as pure time-based
        eviction (sound: the trace is valid under the entry-pressure it
        documents).
\end{itemize}

\subsection{Limits of this analysis}

\begin{itemize}[nosep]
  \item \emph{Lite mode} omits Specula's trace-validation harness phase;
        spec$\leftrightarrow$code correspondence rests on the file:line-annotated
        model plus the executable reproduction tests.
  \item State space is bounded (2 in-flight requests, 1--2 hashes/refs,
        MaxT 2--5, small caps) — finite by construction and fully exhausted in
        every reported run. Violations at these bounds are real; absence of
        violations is proven within the bounds, not beyond.
  \item \code{sign\_credential} uses a separate lighter pipeline and is out of
        scope.
\end{itemize}

\subsection{Commit boundary (F1--F3)}

\textbf{Defect.} \file{enforce.go} produced the signature and marked
\code{issued[sigHash] = true} \emph{before} the single-use
\code{decisions.claim} and the per-op charge loop. The TLC s1 trace shows a
request refused at claim retaining \code{rMut = \{issued\}}; the charge variant
retains \code{\{issued, claimed, charged\}} with counters incremented.

\textbf{Fix.} Commit boundary reordered to: authority re-check $\to$
\code{d.sign} (pure output) $\to$ \code{claim} $\to$ \code{chargeSpend}
(atomic \code{chargeAll} on mandate and global counters; global failure
refunds the mandate charge) $\to$ \code{issuedMark}. A charge refusal calls
\code{decisions.release}. Refused requests now commit nothing — verified by
\code{TestRepro\_RefusedClaimLeavesNoResidue},
\code{TestRepro\_RefSurvivesChargeRefusal}, and
\code{TestRepro\_ChargeIsAtomic}, plus unit tests of \code{chargeAll} and
\code{refund}.
TLC: \textbf{RefusePure passes} (312{,}666 states, exhaustive).

\subsection{Concurrency (F7, F8)}

\textbf{Defect.} \code{d.issued} and \code{d.pendingReq} were plain maps
accessed by per-connection goroutines while every neighboring store was
mutex-guarded. A race-hammer test produced
\code{fatal error: concurrent map writes} — an unrecoverable runtime fatal,
i.e., any client able to open two connections could crash the custodian and
drop every live grant (fail-closed availability violation). Separately,
\code{submitTx}'s check-then-delete let two submitters both pass the issued
check.

\textbf{Fix.} \code{issuedMu} and \code{pendingMu} guard every access;
\code{issuedTake} performs check+delete inside one critical section.
Verified by \code{TestRepro\_IssuedTakeIsAtomic} (sequential + 8-goroutine
single-winner hammer) and \code{TestRepro\_RaceHammer} under \code{-race}.
TLC: \textbf{SubmitOnce passes}.

\subsection{Escalation limiter (F4)}

\textbf{Defect.} \code{limiterFor()} constructed a \emph{new}
\code{escalationLimiter} on every call whenever
\code{policy.Escalation.Rate} was configured, so \code{allow()} always saw an
empty hit window and the configured rate never engaged.

\textbf{Fix.} The configured limiter is built once under \code{limiterMu}
and reused. Verified by \code{TestRepro\_ConfiguredLimiterEngages}
(count=1 refuses the second escalation; identical instance returned).
TLC: \textbf{PendingBound passes} (812{,}713 states).

\subsection{Authorization (F5, F9, F10)}

\textbf{F5 — unguarded agent reactivation (high).} \code{agent\_set\_status}
accepted \code{suspended}$\to$\code{active} (and \code{enrolled}$\to$\code{active})
with only the socket token — asymmetric with mandate reactivation, which
requires a relayed principal ceremony. A token-holding agent could
un-suspend itself. \emph{Fix:} every transition to \code{active} routes through
a bound \code{agent\_activate} WebAuthn ceremony;
\code{AgentSetStatus}/\code{signer agent reactivate} gained an \code{--account}
flag selecting the operator wallet whose passkey authorizes it. Privilege
reductions remain ceremony-free.

\textbf{F9 — authority TOCTOU.} The pipeline sampled grant/escrow/mandate/agent
authority once at E2; revocation mid-request did not stop delivery of the
post-revocation signature. \emph{Fix:} \code{authorityRevoked} re-validates all
mutable inputs immediately before \code{d.sign}. See \S\ref{sec:residuals}
for the remaining commit-tail window.

\textbf{F10 — blind confirms.} \code{completeApproval} minted a bound approval
for whatever \code{requestHash} the client supplied — the escalation funnel
(limiter + pending queue + operator triage) was advisory. \emph{Fix:}
\code{MethodConfirm} refuses hashes absent from \code{pendingReq}; the operator
can only approve requests the daemon actually escalated.
TLC: \textbf{ApprovalBound passes} (754{,}688 states).

\subsection{Persistence (F6, F11)}

\textbf{F6 — restart resurrection.} \code{rebuildIssued} restored \code{issued}
for every \code{signed:} log record; \code{submitted:} records (which carried
the Horizon tx hash, not the payload hash) did not tombstone it, so a payload
submitted pre-restart passed the E5 check again post-restart.
\emph{Fix:} submit records now carry \code{payload\_hash}; rebuild replays the
log sequentially — \code{signed:} adds, \code{submitted:} tombstones, and a
legitimate re-sign re-adds. Verified by
\code{TestRepro\_SubmittedTombstonedOnRestart}.

\textbf{F11 — seen-set aging (accepted bound).} Refs older than 24h are
evictable once the set exceeds 10{,}000 entries; an evicted ref can be
re-claimed, authorizing a second signature for the same decision.
\emph{Disposition:} documented bound — practical impact is bounded and
shrinks further now that refused requests release their refs (F2).
\code{TestRepro\_SeenSetAgingBound} documents the semantics; the s3 hunt
remains violated \emph{by design} under the time-based-eviction abstraction.

\subsection{Hygiene}

\code{MethodDisable} dropped the wallet grant but left \code{mandate:} escrow
entries (keyed by mandate ID) holding seed material in memory. \emph{Fix:}
\code{dropWalletGrants} sweeps every mandate escrow on \code{passkey\_disable}
and \code{remove\_wallet}
(\code{TestRepro\_DropWalletGrantsSweepsEscrows}).

\subsection{Residual bounds}
\label{sec:residuals}

\textbf{F9 commit-tail window.} The s5/s6 traces now require revocation to
land \emph{after} the pre-sign \code{authorityRevoked} re-check and \emph{before}
response delivery — the claim$\to$charge$\to$mark$\to$return tail. In the real
implementation that window shrank from the entire E2$\to$deliver pipeline
(including escalation waits, milliseconds) to microseconds of commit code.
Eliminating it requires revocation to be atomic with delivery — a daemon-level
read lock spanning validation$\to$return on \code{grantStore}/\code{agentRegistry}
(the deferred \code{sync.RWMutex} design). Severity: low; documented.

\textbf{F11} and lazy \code{pendingReq} expiry are documented above.

%==================================================================
\section{Model Artifacts Kept Honest}
%==================================================================

\begin{itemize}[nosep]
  \item \code{EvictDecision} abstracts the $>$10k-entry aging gate as pure time
        eviction — s3 traces are valid under that pressure.
  \item \code{delivered}/\code{submitted}/\code{log} are observability vars;
        hunt cfgs hide them via \code{VIEW} only where neither actions nor the
        checked invariant read them (documented per cfg).
  \item Restart kills in-flight requests to \code{refused} (connection death);
        a mutated-but-refused in-flight request at restart is a real edge the
        model keeps visible via \code{rMut}.
  \item The ceremony path clears \code{agentDirty} — an operator-blessed
        reactivation legitimately restores trust, so post-ceremony signatures
        are not violations.
\end{itemize}

\section{Recommendations}
%==================================================================

\begin{enumerate}[nosep]
  \item Add a \code{go test -race} job for \code{internal/custodian} to CI —
        the F8 class is exactly what it catches.
  \item Add conformance vectors C15 (``refusals are side-effect-free'') and
        C16 (``escalation requires tracked pending'') to the C3--C14 suite.
  \item If revocation promptness ever becomes a hard requirement, implement
        the deferred \code{sync.RWMutex} design spanning E2$\to$delivery.
  \item Re-run the hunts on any change to \file{enforce.go}, \file{grants.go},
        \file{pending.go}, \file{submit.go}, or the agent/mandate lifecycle —
        the cfgs are cheap to replay (\S\ref{sec:appendix}).
\end{enumerate}
